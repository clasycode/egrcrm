# CRM на вашем компьютере — версия 3.6

## Как запустить

1. Скачайте ZIP проекта с GitHub: **Code → Download ZIP**. Распакуйте его полностью в обычную папку, например `Документы\RudyCortex`. Не запускайте из архива.
2. На компьютере должен быть Python **3.12** с компонентом **Tcl/Tk** (в стандартном установщике python.org он выбран). Если Python 3.12 уже установлен, повторная установка не нужна.
3. Дважды нажмите **«Запустить CRM.bat»** (английское имя того же запуска — `start-windows.bat`).
4. Дождитесь подготовки. Только в первый раз или при изменении компонентов потребуется скачать зависимости из интернета. Затем они используются повторно.
5. При новой базе окно предложит придумать логин и пароль владельца. При существующей базе используйте прежние данные. Пароль можно изменить кнопкой **«Восстановить доступ»**, указав логин активного владельца.
6. CRM автоматически откроется в браузере: **http://127.0.0.1:8000**. Войдите и работайте как раньше.

В окне управления есть кнопки открытия CRM, создания переносимой резервной копии, восстановления доступа, открытия журналов и папки данных. После резервирования открывается папка архивов; переносимый архив имеет расширение `.zip`.

**Браузер можно закрыть: сбор продолжится, пока работает окно управления.** Чтобы завершить работу, нажмите **«Остановить и закрыть»**. Во время текущего запроса остановка может занять около 40 секунд. Повторное нажатие файла запуска открывает уже работающую CRM, второй сборщик не создаётся. Если порт занят старым запуском, закройте его; программа не завершает чужие процессы.

Пока ноутбук выключен или спит, сбор и расписание не выполняются. Для обращения к ЕГР нужен интернет. Программа обращается к ЕГР непосредственно с вашего компьютера. Доступность источника может меняться; её ошибки отображаются в CRM. Эта версия открывается только на вашем ПК, без домена, внешнего IP и настройки роутера.

## Где база и как обновлять

Данные хранятся отдельно от скачанной программы:

`%LOCALAPPDATA%\RudyCortex\EGRCRM`

Адрес можно вставить в строку Проводника. Здесь находятся `dev.sqlite3`, локальный ключ, архивы, журналы и среда Python. Не удаляйте эту папку при обновлении. Не пересылайте её посторонним: она содержит клиентскую базу и локальные учётные записи.

1. В работающей CRM скачайте полную ZIP-копию в разделе **«Резервные копии»**. Сохраните копию также на другом носителе.
2. Нажмите **«Остановить и закрыть»** и дождитесь закрытия окна.
3. Распакуйте новую версию в новую папку и запустите **«Запустить CRM.bat»**.
4. Программа использует прежнюю папку данных и логин. Перед обновлением схемы SQLite автоматически создаётся дополнительная копия `before-upgrade-….sqlite3`. Самостоятельно заменять таблицы не нужно.

При переходе со старой версии, где `dev.sqlite3` лежит рядом с `manage.py`, сначала закройте старый запуск и поместите **копию** старых `dev.sqlite3` и `.local-key` в распакованную папку новой программы. Если базы в AppData ещё нет, запуск перенесёт её копированием. Если база в AppData уже есть, она имеет приоритет и не перезаписывается. Для переноса между уже заполненными установками используйте ZIP-восстановление через CRM.

Обычные обновления рассчитаны на движение вперёд. Не запускайте старую версию поверх обновлённой схемы. Для отката сначала сохраните текущее состояние и восстановите соответствующую резервную копию.

## Потом переехать на сервер

Приложение и формат данных общие для ПК и сервера. Когда будет подходящий сервер:

1. Создайте и скачайте переносимую ZIP-копию на ПК.
2. Остановите локальный сбор, чтобы две установки не продолжали независимо собирать данные.
3. Установите эту же или более новую версию на сервер, создайте владельца.
4. В разделе **«Резервные копии»** восстановите ZIP. Восстановление заменяет бизнес-данные, поэтому сначала сохраните отдельную копию, если сервер уже использовался.
5. Проверьте компании и доступность ЕГР, затем включите сбор и расписание: после восстановления они приостановлены.

Переносятся компании, контакты, заметки, задачи, история и результаты обработки. Пароли и секретные настройки в переносимый ZIP не входят; пользователей нужно проверить на новом месте. Формат поддерживает SQLite на ПК и PostgreSQL на сервере. Нативные `.sqlite3`-копии — дополнительная страховка для локального восстановления, для переноса через интерфейс выбирайте ZIP.

## Если не запускается

- Нет окна: запустите английский `start-windows.bat`, проверьте сообщение о Python 3.12 / Tcl/Tk.
- Подготовка не прошла: откройте **«Журналы»**, сохраните `launcher.log`, `web.log`, `worker.log`. Не отправляйте `.local-key` и базу публично.
- Забыли пароль: **«Восстановить доступ»**, прежний логин владельца, новый пароль. Локальная блокировка попыток входа этого владельца сбрасывается.
- Окно сообщает, что CRM уже запускается: найдите прежнее окно. После аварийного завершения повторный запуск освобождает файловую блокировку автоматически; отдельное удаление lock-файла не требуется.
- После аварийного отключения сбор может ждать истечения прежней блокировки задания (до нескольких минут). Сохранённые компании остаются в базе.

Запуск не требует административных прав. Нужна возможность записи в папку распакованной программы (для статических файлов) и AppData. На первом этапе это приложение с окном управления и веб-интерфейсом, а не самостоятельный EXE: установленный Python 3.12 остаётся необходимым.
