# Обновление на Windows 10 без потери базы

1. В чёрном окне CRM нажмите Ctrl+C, дождитесь остановки и закройте окно. Если открыто несколько окон старого запуска, остановите все.
2. Скопируйте **всю вашу текущую папку проекта** в отдельную резервную папку, например `egrcrm-backup`. Эта копия содержит ваши данные и ключ: не отправляйте её другим людям.
3. На https://github.com/clasycode/egrcrm нажмите **Code → Download ZIP**. Распакуйте архив в отдельную новую папку.
4. Из новой папки скопируйте файлы и подпапки **в старую рабочую папку**, согласившись на замену файлов кода. Это объединение папок: **не удаляйте старую папку целиком**. Архив не содержит `dev.sqlite3`, `.local-key` и `.venv`, поэтому при таком копировании база, пароль владельца и окружение сохранятся.
5. В старой рабочей папке запустите **start-windows.bat**. Он обновит зависимости, сохранит дополнительную копию SQLite в `backups`, применит миграции и запустит сайт вместе со сборщиком. Если предлагается снова создать владельца, остановитесь: вероятно, вы запустили новую папку без своей базы.
6. Откройте http://127.0.0.1:8000, войдите и нажмите **Проверка УНП и загрузка**. Если видите старую страницу, нажмите Ctrl+F5.
7. Сначала проверьте УНП **193787017**. На странице задания нажмите «Обновить результат» через несколько секунд. Запросы последовательные и с паузой, поэтому получение сведений может занять время. Успешный результат даёт ссылку на карточку. Ошибка показывает причину; её текст можно прислать в чат.
8. Для новых регистраций за сутки укажите одну и ту же **завершённую дату** в обоих полях и нажмите «Загрузить новые регистрации». Прогресс — в таблице заданий; CSV со списком УНП — в таблице интервалов. Карточки с подходящими контактами появятся в «Новых». Остальные УНП останутся в выгрузке кандидатов.

Если сборщик не отвечает, не нажимайте много раз «Проверить»: перезапустите `start-windows.bat`. Одно повторное нажатие не создаёт параллельных заданий на тот же УНП.

При 401/403/429 источник автоматически приостанавливается. Сначала устраните причину, затем нажмите возобновление и повтор нужного ошибочного задания. Не обходите ограничения ЕГР.

Расписание работает с закрытым браузером, но только пока включён компьютер и работает окно запуска CRM. Для круглосуточной работы нужен сервер. Непроверенный live API нельзя считать работающим только по успешному запуску приложения.

Резервные копии создаются перед миграцией, это не полноценное автоматическое резервирование. Для восстановления остановите CRM и замените `dev.sqlite3` нужной копией; сохраните повреждённую текущую базу отдельно, не затирайте единственный экземпляр.

## ОКЭД, адреса и сбор без ожидания окончания

После обновления во вкладке **Компании** доступны поля «ОКЭД: код или группа», «Исключить ОКЭД» и «Название вида деятельности». Например, `62` отбирает группу, `62010` — код, а `62, 63` — обе группы. Видны все текущие виды, подтверждённый основной вид API не определяет.

Адреса ранее полученных компаний показываются сразу из сохранённых адресных ответов. Для ОКЭД старых карточек откройте **Проверка УНП и загрузка → Дополнить ОКЭД и адреса старых карточек**. Это ставит их на фоновое обновление, не сбрасывает заметки и не запускает заново завершённую годовую загрузку. При первом запросе нового УНП деятельность получается автоматически.

В блоке **Сбор сейчас** счётчики обновляются каждые 3 секунды. «Найдено» означает кандидатов, «обработано» — успешное получение сведений, «доступно в CRM» — компании с подходящими контактами. Счётчик CRM включает ранее имевшиеся карточки. Пока запрашивается сам дневной список, точное число кандидатов ещё неизвестно — оно появляется после сохранения ответа. Общие счётчики могут изменяться и при перепроверках; это не обещание абсолютной полноты источника.

Кнопка **Скачать уже собранные компании (CSV)** выгружает доступные карточки на момент скачивания. Сбор продолжается. В таблице **Сбор по дням** можно отдельно скачать готовые компании одного дня или все найденные УНП (включая ещё не обработанных). Для отфильтрованной выгрузки примените фильтры во вкладке **Компании**, затем нажмите выгрузку над таблицей.

Сама таблица компаний загружается при открытии страницы; для появления новых строк нажмите обновление страницы. Счётчики обновляются без перезагрузки и не сбрасывают введённые фильтры.

## Сборщик запущен, но все счётчики нулевые

Если «Дней: 0 из 0» и «Заданий: 0», сборщик ждёт задания: это не зависший запрос к ЕГР. Проверьте сообщение над блоком прогресса после нажатия загрузки. Период с сегодняшней датой отклоняется целиком, так как день ещё не завершён по Europe/Minsk. Например, 05.11.2026 можно загрузить 03.11.2026–04.11.2026, но не 03.11.2026–05.11.2026. Автоматического обрезания периода нет. После исправления дат нажмите загрузку ещё раз: появится подтверждение принятого периода и дни в очереди.
