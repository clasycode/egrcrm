# Изменения и проверка 3.2 · 05.11.2026

## Изменения для пользователя

- Статус меняется прямо в строке таблицы компаний и клиентов: нажмите текущий статус и выберите новый. Сохранение автоматическое, рядом появляется результат. Счётчик клиентов обновляется сразу.
- Обновление не затрагивает заметки, ответственного, запреты или отметку просмотра карточки. Изменение попадает в историю. Если статус успел изменить другой сотрудник, система отклоняет устаревшую правку и просит обновить список.
- Убрана лишняя вертикальная прокрутка полосы вкладок. Горизонтальная прокрутка широких таблиц и вкладок на телефоне сохраняется там, где она нужна.
- Исправлен размер и цвет стрелки в кнопке «Проверить УНП» пустого списка. Переход ведёт непосредственно к форме проверки. Пустой список не показывает шапку широкой таблицы, кнопки переносятся с промежутками.
- Статистика разделена на показатели базы сейчас и результаты за выбранный период. Периоды: 7/30/90 дней или свои даты до 366 дней; по умолчанию 30 дней. Есть график пополнения и обращений, диаграммы результатов, статусов, контактов, географии, деятельности и возраста компаний. Статусы, регионы и ОКЭД ведут к соответствующим спискам компаний.
- У графиков есть точные числа, подписи и доступная таблица динамики. Пустые данные не показываются как успешная конверсия. Некорректные даты дают понятную ошибку.

## Правила расчёта

Период включителен, по Europe/Minsk. Пополнение считается по дате допуска в CRM, возраст — по дате регистрации. База, непросмотренные компании, текущие статусы и просроченные задачи относятся к текущему состоянию и не меняют смысл при выборе периода.

Обращения — вручную записанные звонки и сообщения. Число обращений может превышать число компаний. Результаты считаются по уникальным компаниям с обращением в выбранном периоде; результат должен быть не раньше первого обращения в этом периоде и не позже его конца. Простая смена статуса и заметка не заменяют запись результата. Ответ/переговоры/клиент/отказ могут пересекаться по компаниям, поэтому строки не складываются.

Проценты распределений относятся ко всей CRM; проценты результатов — к компаниям с обращениями. Длина столбцов отражает этот процент. Телефон и email пересекаются; наличие нескольких телефонов не увеличивает число компаний. «Только исторические» исключает компании хотя бы с одним текущим телефоном. Один субъект может иметь несколько текущих видов деятельности.

## Проверка

- Django/SQLite: 90 тестов, 89 успешно, 1 пропущен — конкурентные блокировки требуют PostgreSQL.
- Отдельно проверены расчёты по датам и последовательности событий, повторные обращения и исторические контакты, неизвестные даты, пустые данные, недопустимый период.
- Проверены права менеджера, обязательность POST/CSRF, защита от устаревшей правки, запись аудита, безопасный возврат без JavaScript и сохранность остальных полей карточки.
- Chromium/Linux: фактическая смена статуса без открытия карточки, откат при HTTP 409, обновление счётчика клиентов, выбор строк и прокрутка после автообновления, работоспособность нового селектора после замены HTML таблицы.
- Вкладки на десктопе: высота содержимого совпадает с высотой контейнера — вертикальная прокрутка отсутствует. Стрелка в кнопке УНП — 18×18 px.
- Статистика проверена на ширинах 360/390/768/1440 px без переполнения документа. Ошибок JavaScript не обнаружено.
- `makemigrations --check --dry-run`: изменений моделей нет. `collectstatic`: успешно.

Windows 10/Edge и PostgreSQL в этой итерации отдельно не запускались. Реальный API ЕГР не вызывался. Демонстрационные записи и события использовались только в отдельной временной базе и не входят в обновление.

## Обновление

Сначала скачайте резервную копию через интерфейс, остановите программу, обновите файлы приложения, запустите `start-windows.bat` и обновите браузер сочетанием Ctrl+F5. Существующую папку данных сохраняйте. Версия 3.2 не изменяет схему БД.
