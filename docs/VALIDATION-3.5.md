# Читаемые таблицы и обычный текст карточки · 3.5 · 05.11.2026

## Таблицы

- Более заметные заголовки, ровные отступы, разделители колонок, чередование фона строк и выделение выбранной строки/фокуса.
- В основной таблице сначала видно название, затем УНП и даты. Повторяющиеся юридические префиксы вроде «Общество с ограниченной ответственностью» убраны только из отображаемого заголовка строки. Полное название остаётся в подсказке, доступном имени ссылки, карточке, поиске и копировании; база не переименовывается.
- Инициалы рассчитываются по узнаваемому названию без юридического префикса. Устойчивый цвет знака компании не меняется.
- Копирование вынесено в компактную кнопку рядом с названием. Телефон выделен сильнее email и служебных сведений. ОКЭД оформлен отдельным маркером, город — основной строкой, адрес — вторичной.
- Длинные деятельность/адрес ограничены несколькими строками в таблице; полный текст доступен в подсказке и карточке. Широкая таблица прокручивается внутри контейнера, который доступен с клавиатуры.
- Сохранены смена статуса, массовый выбор и маркеры запретов/клиентов.

## Копирование без JSON

Кнопка получает `text/plain`, а не JSON-ответ, и копирует готовый текст разделами:

КАРТОЧКА КОМПАНИИ → РАБОТА С КОМПАНИЕЙ → АДРЕС И ГЕОГРАФИЯ → КОНТАКТЫ → ВИДЫ ДЕЯТЕЛЬНОСТИ / ОКЭД → ЗАДАЧИ → ОБРАЩЕНИЯ И РЕЗУЛЬТАТЫ → ИТОГИ ОБРАБОТКИ → ПОИСК САЙТА → ИСТОРИЯ ИЗМЕНЕНИЙ CRM.

Сырые ответы и снимки ЕГР больше не включаются. Изменения CRM выводятся человеческим текстом, например `Статус: Новая → Клиент`, без технических словарей `before/after`. Полное название, заметки, задачи и остальная полезная информация не обрезаются. Буфер обмена и запасной диалог ручного копирования работают как раньше.

## Telegram и Viber

Надёжной общедоступной проверки наличия аккаунта по произвольному номеру нет. Telegram API импорта контактов требует пользовательской авторизации и ограничен приватностью/лимитами; Viber Bot API получает данные по Viber user ID, а не проверяет произвольный телефон. Неудачный переход не доказывает отсутствие регистрации.

Поэтому фоновых проверок, импорта телефонных книг и запросов к мессенджерам в этой версии нет. Реализованы **ручные отметки**:

1. Нажмите значок настроек рядом с иконками мессенджеров либо откройте проверку контакта в карточке.
2. Для каждого сервиса выберите «Не проверено», «Найден вручную» или «Не найден при ручной проверке».
3. Сохраните. «Не найден» скрывает только соответствующую иконку в таблице, фрагменте автообновления и карточке.
4. Если требуется вернуть ссылку, выберите «Не проверено» или «Найден вручную».

Это ваш результат ручного поиска, а не подтверждение отсутствия регистрации. Настройки приватности могут мешать найти существующий аккаунт. Отметка уже нажатой ссылки остаётся отдельным признаком и не считается проверкой аккаунта.

Старые номера получают состояние «Не проверено», без ложного скрытия. При изменении ручного номера его отметки сбрасываются. Обычная проверка контакта, не передающая новые поля, сохраняет уже существующие отметки. Изменения записываются в историю проверки и CRM и входят в резервную копию.

Справочные ограничения API:
- https://core.telegram.org/method/contacts.importContacts
- https://developers.viber.com/docs/api/rest-bot-api/#get-user-details

## Проверка

- 104 Django-теста на SQLite: 103 успешно, 1 пропущен — требует PostgreSQL.
- Проверены обычный текст ответа/аудита, исключение сырых данных, сохранность полного названия и короткое отображение, скрытие каналов по отдельности, обратное включение и сброс при смене номера.
- Проверены сохранение отметок в новой копии и восстановление старого архива без новых полей: состояние становится «Не проверено».
- Chromium/Linux: фактическое копирование текста в буфер без JSON, ручная отметка и видимость соответствующей иконки в карточке/таблице, выбор строк и смена статуса.
- На подготовленной строке таблицы высота составила 136,5 px при ширине окна 1440 px. На 390 px проверены список, карточка, прогресс сбора и кандидаты — переполнения документа нет. Ошибок JavaScript не обнаружено.
- Миграция 0016 добавляет два поля состояния к контакту, существующие записи получают безопасное значение `unknown`. `makemigrations --check --dry-run`: дополнительных миграций нет. `collectstatic`: успешно.

Windows 10/Edge и PostgreSQL в этой итерации отдельно не запускались. ЕГР, Telegram и Viber не опрашивались. Снимки сделаны на отдельной временной базе с вымышленными компаниями.
