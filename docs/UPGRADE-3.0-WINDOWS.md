# Первое обновление до 3.0 — Windows 10

1. Остановите старую CRM: Ctrl+C в чёрном окне, затем закройте окно. Не запускайте старую и новую версии одновременно.
2. Сделайте копию **всей старой папки**. Особенно сохраните `dev.sqlite3` и `.local-key`. Не удаляйте её до проверки обновления.
3. На GitHub нажмите Code → Download ZIP. Распакуйте архив отдельно.
4. Скопируйте новые файлы **поверх старой рабочей папки**, согласившись заменить файлы программы. Не удаляйте `dev.sqlite3` и `.local-key`.
5. Запустите `start-windows.bat` **в этой старой рабочей папке с обновлёнными файлами**. При первом запуске новой версии она копирует прежнюю SQLite-базу и ключ в `%LOCALAPPDATA%\RudyCortex\EGRCRM`, оставляет старые файлы на месте, делает копию перед миграциями и обновляет схему.
Если старый сервер ещё работает на порту 8000, перенос остановится с сообщением; сначала закройте старое окно.

6. Откройте CRM, проверьте ваши компании и заметки. В «Диагностика» должны отображаться версия 3.0.0 и новый путь данных. Если вместо вашего входа предлагается заново создать владельца, остановитесь: вероятно, запущена другая папка без прежней базы. Не продолжайте работу в пустой базе.
7. В «Резервные копии» нажмите «Создать и скачать резервную копию». Сохраните ZIP отдельно от компьютера/диска с CRM.

## Следующие обновления

База уже хранится отдельно от программы в AppData. Можно заменить файлы программы или распаковать следующую версию в другую папку на **том же Windows-аккаунте** и запустить её: по умолчанию используется прежнее хранилище. Перед миграциями каждый запуск делает дополнительную SQLite-копию в `backups`.

Не запускайте после миграции старую версию: её схема может быть несовместима. Не возвращайте старый `dev.sqlite3` поверх новой базы без резервной копии. Для переезда на другой компьютер используйте переносимый ZIP из раздела резервирования.

## Выгрузить → обновить → загрузить базу

1. Создайте и скачайте ZIP в «Резервные копии» старой установленной версии (начиная с 3.0).
2. Установите такую же или более новую версию. На новом компьютере создайте владельца.
3. Остановите/сбросьте сбор и дождитесь завершения активного запроса.
4. В «Резервные копии» выберите ZIP, отметьте замену, если в новой установке уже есть рабочие записи, и введите `ВОССТАНОВИТЬ`.
5. После восстановления проверьте компании, контакты, заметки, задачи и историю. Предыдущее состояние автоматически сохраняется дополнительным ZIP.
6. При необходимости выдайте менеджерам доступ в «Настройки». Пароли не переносятся: текущий владелец сохраняет свой вход, новые имена пользователей восстанавливаются выключенными. Владелец задаёт пароль и доступ менеджера.
7. Явно возобновите источник и включите нужное расписание. Восстановление не начинает сбор автоматически.

Архив от более новой схемы не загружается в старую программу: сначала обновите программу. Контрольная сумма обнаруживает случайное повреждение, но не является подписью доверенного автора — используйте только собственные копии. Серверные ключи и пароли в ZIP не включены. Полная SQLite-копия перед миграцией может содержать хеши паролей; храните её приватно.

Интерфейс принимает ZIP до 100 МБ, распакованные данные — до 500 МБ. Для больших баз администратору следует использовать PostgreSQL pg_dump/pg_restore и план обслуживания. Пока не проверялась база на миллионы записей.

## Внешняя резервная папка

Можно задать `CRM_BACKUP_COPY_DIR` в переменных Windows/сервера, например путь другого диска или смонтированного защищённого хранилища. Созданные архивы дополнительно копируются туда. Копия только в AppData не защищает от потери компьютера. Не удаляйте папку данных при обновлении.
