# Проверки версии 3.0 — 05.11.2026

- Полный набор PostgreSQL: 78 тестов, все прошли. Включён реальный конкурентный тест ручного редактирования и импорта с отдельными соединениями.
- SQLite: функциональный набор проходит; конкурентный тест PostgreSQL пропускается явно. Это не тест блокировок SQLite на уровне PostgreSQL.
- Миграция базы со схемы 0003 до текущей: сохранены записи, ручные заметки/статусы/запреты и незавершённая очередь.
- Реальный перенос SQLite → PostgreSQL → SQLite через ZIP: сохранились карточка, заметка, контакт, задача и ответственный. Проверочные данные находились в отдельных временных базах, не в рабочей CRM.
- Проверены восстановление через HTTP, замена с подтверждением, контрольная сумма, отказ новой схемы, отказ посторонних таблиц, откат некорректных FK и отсутствие автоматического возобновления платных поисков.
- Проверены роли менеджера/владельца, CSRF сброса, запреты обращений, лимит входа, текстовые XLSX-ячейки и безопасный CSV.
- Проверена логика переноса старого SQLite в отдельную папку данных: оригинал сохраняется, повторный запуск не заменяет более свежую стабильную базу, работающая старая CRM блокирует перенос.
- Серверный Docker-образ собран с проверкой TLS через доверенный CA; обнаруженная проблема прав файлов устранена, Gunicorn запускается непривилегированным пользователем.
- HTTP 200 из Gunicorn + PostgreSQL подтверждён для входа, компаний, прогресса, таблицы заданий, задач, резервирования, настроек, статистики, диагностики и JavaScript. Один цикл worker обновил heartbeat, не отправляя запросов при паузе источника.
- Compose проходит `config --quiet`; `makemigrations --check --dry-run`, Django check и синтаксис JavaScript проходят.
- Production `check --deploy` оставляет только предупреждения W005/W021 о необязательном HSTS для всех поддоменов и preload. Эти параметры требуют решения владельца домена и готовности HTTPS на поддоменах; автоматически не включались.

## Практические ограничения проверки

Native Windows BAT/браузер не запускались на машине заказчика. Файловая логика проверялась Python-тестом. Не проверены доступ к ЕГР и реальное расписание на будущем сервере, реальный ключ/тариф Brave, внешний диск/облачное резервное хранилище и миллионные объёмы. Моки провайдера не выдаются за живую интеграцию. При развёртывании нужны ограниченный API-пилот, независимый запуск расписания с закрытым браузером, HTTPS и восстановление внешней копии на выбранном сервере.

## Ограниченный замер на искусственных данных

Отдельный PostgreSQL, 10 000 карточек, по одному телефону и виду деятельности, короткий адрес, без объёмной истории HTTP-ответов: первый прогресс 0,034 с, повтор из кеша <0,001 с; CSV 1,90 с (1,56 МБ); XLSX 3,73 с (0,57 МБ); ZIP-копия 1,62 с (0,27 МБ). Данные однотипные и хорошо сжимаются. Эти числа характеризуют только данный стенд и не являются оценкой годовой загрузки ЕГР, объёма исходных ответов или обещанием скорости на будущем сервере.
