# EGR CRM — RudyCortex

Версия с интерфейсом загрузки закрытой CRM для Беларуси. Архитектура: Django 5.2, PostgreSQL на обычном сервере, отдельный последовательный сборщик. Размещение на Sites не требуется. Репозиторий содержит исходное ТЗ и предоставленный Swagger в `docs/`.

## Локальная разработка

Python 3.12+. Из корня репозитория:

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.txt
# Создайте случайный ключ и передайте через окружение. Не коммитьте ключ.
export DJANGO_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export DEBUG=1
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py run_local
```

Без POSTGRES_HOST используется локальный SQLite (игнорируется Git). `.env` автоматически не читается. Для PostgreSQL задайте POSTGRES_HOST, POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, при необходимости POSTGRES_PORT в окружении процесса. Миграции те же. Доступ к CRM имеет только активный пользователь с is_staff; публичной регистрации нет. Администратор создаёт разрешённых пользователей.

```sh
.venv/bin/python manage.py test
.venv/bin/python manage.py check
# Первый ограниченный пилот: не запускать массовую загрузку до проверки ответов
.venv/bin/python manage.py collect_egr --unp 193787017
.venv/bin/python manage.py collect_egr --day 2026-11-03 --limit 1
# После успешного пилота: вычисление 365 завершённых дней на дату запуска
.venv/bin/python manage.py collect_egr --initialize --limit 10
# Следующие небольшие порции, с продолжением по контрольным точкам
.venv/bin/python manage.py collect_egr --limit 10
```

Дневная выборка использует getBaseInfoByPeriod, фильтрует nkscrt=1 и локальную дату регистрации. Эквивалентность выборки реальным регистрациям ещё необходимо проверить живым пилотом. Контакты не разбиваются и не нормализуются догадками: исходные строки сохраняются. Текущий метод определяет актуальность, история хранится отдельно. Сведения источника обновляются без сброса заметок, статуса и запрета. Кандидаты без контактов не видны в рабочем списке.

401/403/429 приостанавливают источник. Причина доступна в SourceControl через admin. Возобновлять только после устранения причины. Установленный locked_until защищает от параллельных сборщиков; после аварии аренда истекает через 5 минут после последнего запроса. Не удаляйте блокировку работающего процесса.

## Развёртывание

Перед оплатой длительного тарифа проверить HTTPS-доступ к ЕГР с выбранного сервера. Веб, PostgreSQL и сборщик размещаются на сервере; браузер не хранит базу. Для production обязательны HTTPS reverse proxy, WSGI-сервер (например, gunicorn, устанавливается отдельно), DEBUG=0, случайный DJANGO_SECRET_KEY, точный ALLOWED_HOSTS и PostgreSQL. Django принудительно перенаправляет на HTTPS при DEBUG=0. Настройку доверенных proxy-заголовков выполнять только вместе с защищённым reverse proxy; произвольным клиентским заголовкам доверять нельзя.

Для Windows: [пошаговое обновление без потери базы](docs/UPDATE-WINDOWS.md). `start-windows.bat` запускает веб и фоновый сборщик вместе. На сервере запускайте `manage.py egr_worker` отдельным контролируемым сервисом рядом с WSGI.

Это ещё не готовая production-поставка. PostgreSQL и доступ к ЕГР с будущего сервера не проверены; сервер не куплен и не настроен. Планировщик реализован в сборщике; его работа на целевом сервере, резервирование и восстановление должны быть проверены до эксплуатации.

## Реализовано и проверено

- Вход и серверный доступ только разрешённым пользователям; список и поиск, «Новые», карточка, заметки/статус/запрет с журналом.
- Проверка УНП из интерфейса: фоновое получение сведений и контактов, ссылка на карточку или явное объяснение недопуска/ошибки.
- Дневная загрузка и период до 365 завершённых дней, начало годовой загрузки, сохранение прогресса, повтор ошибочного задания, пауза/возобновление источника.
- Выгрузка УНП каждого дня в CSV (включая кандидатов без контактов), CSV отфильтрованных компаний, защита текстовых значений от формул.
- Получение текущих видов деятельности через getVEDByRegNum; хранение нескольких ОКЭД без предположения об основном. Фильтр по коду/группе (например, 62), нескольким группам и исключениям; поиск по названию деятельности без учёта регистра. Адрес из текущего метода ЕГР виден в списке, карточке и CSV.
- Фильтры типа, CRM-статуса, регистрации, наличия/актуальности контактов и запрета, поиск и страницы результатов.
- Автообновляемые каждые 3 секунды счётчики на страницах компаний и загрузки: уникальные УНП, обработанные кандидаты, доступные карточки, без контактов, прогресс дней и текущий УНП. CSV готовых компаний отдельного дня и всей CRM доступен во время сбора; экспорт не меняет очередь и не ставит источник на паузу.
- Кнопка дополнения старых карточек, для которых ОКЭД ещё не запрашивался, с сохранением ручных полей.
- Ежедневное расписание (по умолчанию выключено), настройка времени 09:00 Europe/Minsk и перепроверки 7 дней; выполняется процессом сборщика без браузера. Одно выполнение расписания на локальную дату.
- Сброс сбора с предварительным подтверждением: отмена очереди, отключение расписания, пауза источника, сохранение компаний/ручных полей/завершённых интервалов. Поколение сбора и проверки перед записью не позволяют старому запросу возобновить отменённое задание. Сбросы протоколируются в CollectionReset.
- Статистика базы и распределение CRM-статусов с определениями. Это не статистика звонков и продаж.
- Автоматическая дополнительная SQLite-копия перед миграциями в Windows launcher; это не проверенное production-резервирование.

45 автоматических тестов: допуск ЮЛ/ИП, история и идемпотентность, ручные правки, Минск/UTC, авторизация, экранирование, ошибки 204/503/429, очередь UI → worker → карточка, дневная выборка → CSV, отсутствие повторной загрузки завершённого дня, расписание/часовой пояс, безопасный экспорт и фильтры. Дополнительно проверены получение/изменение деятельности, фильтры ОКЭД/названия, сохранность старых карточек, частичная выгрузка с последующим продолжением сбора, текущий УНП и уникальность счётчиков. Отдельно проверена миграция старой базы с сохранением ручных полей и незавершённой очереди. Все данные в тестах искусственные. Проверены миграции и локальный HTTP-запуск; Windows и целевой PostgreSQL ещё не проверены.

## Остаток ТЗ — пока не реализовано

1. Проверка live API с компьютера заказчика/целевого сервера, эквивалентность дневной и пакетной выборок, PostgreSQL-проверки.
2. Автоматический повтор отсутствующих контактов через 7/30 дней. Ручной повтор уже доступен по УНП.
3. Полная версионность каждого контакта и адреса, география в фильтрах, нормализация и разбор телефонов, ручные контакты и проверки номеров.
4. Задачи, ответственные в интерфейсе, настраиваемые статусы, сохранённые подборки, массовые действия, Excel и экспорт выбранных строк.
5. Учёт фактических обращений/ответов и статистика продаж, уведомления об изменениях, стоп-лист по контактам.
6. Проверенное восстановление резервной копии и production-развёртывание, включая независимую проверку расписания на сервере.
7. Ручной поиск сайта через провайдера: пока не подключён. vsite показывается как контакт ЕГР, не как подтверждённый сайт.

Демонстрационные компании в рабочую базу не добавляются. Ошибки источника не считаются отсутствием данных. Не обещается абсолютная полнота ЕГР. Эта версия не является выполнением всего ТЗ.

Технический и UX-разбор текущей версии: [аудит от 05.11.2026](docs/TECH-UX-REVIEW-2026-11-05.md). Остальные рекомендации аудита не реализовывались без выбора приоритетов заказчиком.
