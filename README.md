# EGR CRM 3.4 — RudyCortex

Закрытая CRM для поиска и ручной работы с организациями/ИП Беларуси. Django 5.2, SQLite для Windows, PostgreSQL для сервера, отдельный фоновый worker. Первичные данные ЕГР не требуют ИИ. Сервис не звонит и не рассылает сообщения.

**Версия 3.4:** личный дневной план и аналитика обработки, структурированное копирование полной карточки, текстовый логотип, квадратный аватар и отступы select — [подробности, обновление и снимки](docs/VALIDATION-3.4.md). Добавляется миграция 0015 без изменения существующих таблиц компаний.

**Версия 3.3:** Telegram/Viber у телефонов, поиск компании в Google, отметки нажатых ссылок и выровненные настройки — [подробности и снимки](docs/VALIDATION-3.3.md).

**Версия 3.2:** смена статуса прямо в таблице, исправленные вкладки и кнопка УНП, новая статистика с графиками — [что изменилось и как проверено](docs/VALIDATION-3.2.md).

**Дизайн-система 3.1:** [дизайн-система и сценарии](docs/DESIGN-SYSTEM.md). При обновлении сохраняйте существующую папку данных; перед заменой программы скачайте полную копию в разделе «Резервные копии». Для установки 3.0+ данные уже находятся отдельно от программы.

**Windows: [первое обновление до 3.0 без потери базы](docs/UPGRADE-3.0-WINDOWS.md).** Затем `start-windows.bat`: обновление зависимостей, перенос старой базы копированием в AppData, резервная копия перед миграциями, владелец при новой установке, запуск web + worker. Данные по умолчанию `%LOCALAPPDATA%\RudyCortex\EGRCRM`, отдельно от папки программы. Старый `dev.sqlite3` не удаляется.

## Резервирование и перенос

Вкладка **Резервные копии**: скачать переносимый проверяемый ZIP, восстановить в такой же/новой версии с явным подтверждением. Сохраняются компании, контакты, заметки, задачи, история источника и CRM, подборки, запуски. Пароли и серверные секреты не экспортируются; пользователи сопоставляются по имени, неизвестные создаются выключенными. Восстановление заменяет бизнес-данные атомарно, оставляет дополнительную копию прежнего состояния, останавливает сбор/расписание. Неподдерживаемая новая схема, повреждённая сумма, посторонние таблицы и некорректные связи отклоняются.

Ежедневные архивы создаются работающим worker; SQLite дополнительно копируется перед миграциями. `CRM_BACKUP_COPY_DIR` позволяет копировать архивы во внешнюю смонтированную папку. Для больших серверных баз нужен также pg_dump/pg_restore. Храните копии вне исходного диска.

## Возможности

- Проверка УНП; загрузка завершённых дней/периода/года; отдельные запуски и выгрузки; прогресс с текущим УНП, осторожной оценкой скорости/времени, пауза, сброс, ограниченные повторы ошибок.
- Независимое обогащение кандидатов: ошибка одной компании не блокирует остальные; явная пауза источника на 401/403/429. Отсутствие данных не подменяет ошибку. Дневные/периодные методы можно сопоставить отдельной командой.
- Ежедневное расписание Europe/Minsk с дозагрузкой дней простоя; контакты без результата перепроверяются через 7 и 30 дней от первого отсутствия, есть техническая очередь и ручной повтор.
- ЮЛ с телефоном/email; ИП только с телефоном. Идентичность страна+УНП. Источник обновляет только свои поля, не заметки/статусы/запреты. Текущий/исторический контакт и исходная строка сохраняются.
- Деятельность, ОКЭД, адрес, география, состояние ЕГР; фильтры, Unicode-поиск названия/нормализованных контактов, группы/исключения ОКЭД, справочник полученных кодов.
- История изменившихся ответов с адресами и контактами; уведомление об изменении источника отдельно от новой карточки.
- Ручные контакты; разбор нескольких телефонов только при уверенном распознавании; нормализация без изменения оригинала; проверки ЛПР/общий/неверный и др., комментарии, автор/дата, запреты компании/контакта, предупреждение общего номера и повторного обращения.
- Задачи сегодня/просроченные/предстоящие/выполненные, ответственные, ручной журнал звонков/сообщений/ответов, читаемая лента, настраиваемые CRM-статусы.
- Сохранённые фильтры; выделение строк и массовые статусы/ответственные/задачи; CSV порциями и XLSX с текстовыми типами ячеек, выбор строк/всего фильтра; заметки в экспорт добавляет владелец явно.
- Раздельные показатели базы и продаж с определениями и знаменателями; распределение по географии/деятельности/возрасту/типу, задачи и причины отказа.
- Роли владельца/менеджера, ограничение попыток входа, диагностика и номер версии. Старые staff-аккаунты без профиля сохраняют права владельца для совместимости; новые менеджеры не получают staff.
- Ручной поиск сайтов через Brave Search в фоне с подтверждением возможных расходов. Без ключа — «Не настроено». Автоматического подтверждения принадлежности сайта нет.

## Разработка

Python 3.12+:

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.txt
export DJANGO_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(64))')"
export DEBUG=1
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py run_local
```

`CRM_DATA_DIR` задаёт постоянную папку базы/архивов. Без него для Linux-разработки используется корень checkout. `.env` не читается Django автоматически; Compose передаёт его как окружение. Для PostgreSQL задайте POSTGRES_HOST/PORT/DB/USER/PASSWORD. Каждый cloud task уже изолирован: используйте существующий checkout, не создавайте worktree без явного запроса пользователя.

```sh
.venv/bin/python manage.py test
.venv/bin/python manage.py check
.venv/bin/python manage.py collect_egr --unp 193787017 --limit 1
.venv/bin/python manage.py collect_egr --day 2026-11-03 --limit 10
.venv/bin/python manage.py backup_crm
.venv/bin/python manage.py restore_crm /path/to/archive.zip --owner owner --replace
```

Команды сбора используют ту же очередь и источник, что интерфейс. Массовая загрузка не запускается при установке. В тестах искусственные данные, в рабочую базу демонстрационные компании не добавляются.

## Сервер и ограничения

[Развёртывание, проверка расписания, HTTPS и ключ поиска](docs/SERVER.md). Docker Compose сохраняет PostgreSQL и архивы в volumes. Никогда не удаляйте volumes при обновлении. Доступ ЕГР и независимый запуск расписания проверяются с конкретного сервера; тесты в этой среде не доказывают это. Native Windows GUI запуск здесь не исполнялся; логика переноса файлов и сохранения прежней базы проверяется отдельным тестом.

Архив через UI: до 100 МБ сжатого файла / 500 МБ JSON; для больших баз — серверные дампы. Нет замера на миллионах строк. Полнота ЕГР не обещается; пакетные оптимизации выключены до сравнения живых ответов. Внешний поиск без пользовательского ключа/тарифа не проверен. Автоматический перенос прав и паролей из чужого архива намеренно не выполняется.

Проверки 3.4: 100 тестов на SQLite (99 успешно, 1 требует PostgreSQL), браузер на компьютере и телефоне; [результаты и снимки](docs/VALIDATION-3.4.md). Предыдущая проверка 3.0: 78 тестов на PostgreSQL — [подробности](docs/VALIDATION-3.0.md).

Исходное ТЗ и Swagger — в `docs/`. Исторический [технический/UX-аудит](docs/TECH-UX-REVIEW-2026-11-05.md), [результат доработок 3.0](docs/IMPLEMENTATION-3.0.md).
